# یادداشت امنیت و مسیر آماده‌سازی وردپرس

این شاخه فقط لایه رابط کاربری HTML را تکمیل می‌کند. ظاهر فرم یا داشبورد به‌معنای وجود سرویس امن نیست.

## مواردی که باید پیش از انتشار عملیاتی پیاده‌سازی شوند

1. **احراز هویت:** نشست امن وردپرس؛ کوکی‌های Secure/HttpOnly/SameSite، خروج امن، بازیابی رمز و محدودسازی تلاش ورود. هرگز نقش کاربر را از فرم، query string یا localStorage نپذیرید.
2. **مجوزدهی:** تعریف نقش‌ها و capabilityهای حداقلی مانند مدیر همایش، دبیر، نویسنده، داور و شرکت‌کننده. کنترل دسترسی در هر درخواست سمت سرور انجام شود؛ مخفی‌کردن لینک کافی نیست.
3. **CSRF و فرم‌ها:** استفاده از nonce وردپرس و بررسی آن در handlerهای سمت سرور، همراه با اعتبارسنجی نوع/محدوده ورودی، sanitize و escape خروجی متناسب با context.
4. **ارسال مقاله:** محدودیت حجم و پسوند، بررسی MIME واقعی و امضای فایل، نام‌گذاری تصادفی، عدم اعتماد به نام فایل، ذخیره خارج از مسیر عمومی یا محافظت‌شده، کنترل دسترسی دانلود و اسکن فایل. اعتبارسنجی JavaScript فقط برای تجربه کاربری است.
5. **XSS و SQL injection:** استفاده از APIهای امن وردپرس، `$wpdb->prepare` برای SQL، و توابع escaping مانند `esc_html`, `esc_attr`, `esc_url`, `wp_kses_post` هنگام نمایش.
6. **پیامک و سرویس‌های بیرونی:** کلید API فقط در سمت سرور/مدیریت اسرار، محدودیت نرخ، ثبت نتیجه ارسال، رضایت گیرنده و امکان لغو دریافت. هرگز کلید را داخل HTML یا JS قرار ندهید.
7. **حریم خصوصی:** حداقل‌سازی داده، تعیین زمان نگهداری، سیاست حذف/خروجی داده، دسترسی محدود به فایل‌های مقاله و سوابق داوری.
8. **ثبت رویداد و پشتیبان‌گیری:** ثبت تغییرات حساس (وضعیت مقاله، تخصیص داور، پرداخت، صدور گواهی)، پشتیبان‌گیری رمزگذاری‌شده و آزمون بازیابی.
9. **پرداخت:** تأیید پرداخت فقط با اعتبارسنجی callback سمت سرور و استعلام از درگاه؛ هرگز به پیام موفقیت مرورگر اعتماد نکنید.
10. **آزمون انتشار:** آزمون واحد/یکپارچه، تست دسترسی نقش‌ها، تست فایل‌های مخرب/بزرگ، بررسی امنیتی افزونه‌ها، HTTPS و تنظیمات سرور.

## مدل داده پیشنهادی

- Conference و ConferenceEdition
- UserProfile و Membership/Role
- Paper و PaperAuthor و PaperFile
- ReviewerProfile و ReviewAssignment و Review
- Registration و Payment و Invoice
- Message و Notification و SmsLog
- Certificate و CommitteeMember و Post

همه رکوردهای وابسته باید به شناسه دوره همایش متصل باشند تا سامانه چندهمایشی و چنددوره‌ای قابل اتکا باشد.

## معیار پذیرش رابط HTML

- نمایش مناسب در موبایل، تبلت و دسکتاپ و پشتیبانی از RTL.
- کنترل‌های تعاملی دارای label و focus قابل مشاهده باشند.
- جدول‌های عریض در صفحه کوچک اسکرول افقی داشته باشند.
- هیچ پیام یا دکمه‌ای ادعا نکند داده ذخیره/ارسال شده، مگر اینکه backend واقعی آن را تأیید کرده باشد.

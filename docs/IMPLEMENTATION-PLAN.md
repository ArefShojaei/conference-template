# برنامه اصلاح و اجرای پروژه

این برنامه برای مخزن HTML ایستا است؛ قالب نهایی وردپرس در این مرحله ساخته نمی‌شود.

## مرحله ۱ — پاک‌سازی رابط ایستا
- [x] اصلاح پیام فرم‌ها تا وانمود به ذخیره موفق داده نکنند.
- [x] بهبود اعتبارسنجی مرورگری و بازخورد خطا.
- [x] بررسی اولیه نوع/حجم فایل مقاله در مرورگر.
- [x] بهبود انتخاب فایل و دسترسی صفحه‌کلید.
- [x] مستندسازی محدودیت‌ها و یافته‌های ممیزی.
- [ ] آزمون دستی همه صفحات در مرورگرهای هدف و در اندازه‌های مختلف.

## مرحله ۲ — تکمیل تجربه کاربری ایستا
- جایگزینی داده‌های نمونه با اطلاعات واقعی و تأییدشده.
- افزودن راهنمای نویسندگان و قالب مقاله واقعی.
- تعیین مقصد واقعی برای دکمه‌های جزئیات، مشاهده، دانلود و صفحه‌بندی یا غیرفعال‌کردن آن‌ها تا زمان پیاده‌سازی.
- بررسی لینک‌های داخلی، خطاهای کنسول/شبکه، منوی موبایل، تب‌ها و مودال‌ها.
- بررسی کنتراست، focus، برچسب فرم‌ها، پیام خطا و استفاده با صفحه‌کلید.

## مرحله ۳ — تصمیم‌های محصول پیش از backend
- تعریف همایش و دوره، محورهای علمی، مهلت‌ها و تعرفه‌های مستقل.
- تعریف گردش کار ثبت‌نام، وضعیت‌ها، و سیاست نگهداری داده.
- تعیین فرایند ارسال مقاله، انواع/اندازه فایل، دسترسی و نگهداری امن.
- انتخاب درگاه پرداخت و تعریف پرداخت دستی، رسید، تأییدکننده و سابقه تغییر وضعیت.
- تعیین دامنه نسخه اول برای داوری، پیام‌ها، گواهی و گزارش مالی.

## مرحله ۴ — سامانه عملیاتی (پروژه جداگانه)
- احراز هویت و مجوزدهی سمت سرور.
- پایگاه داده و اتصال همه رکوردها به همایش/دوره صحیح.
- بارگذاری امن فایل با اعتبارسنجی سمت سرور و کنترل دسترسی.
- ثبت‌نام واقعی، پرداخت آنلاین/دستی، رسید و گزارش.
- آزمون‌های واحد/یکپارچه، بررسی امنیتی، پشتیبان‌گیری و راهنمای استقرار.

## معیار پذیرش نسخه ایستا
1. فرم‌ها اعلام نمی‌کنند داده‌ای ذخیره شده است.
2. فیلدهای الزامی خطای قابل فهم دارند.
3. فایل مقاله از نظر اولیه PDF و حجم بررسی می‌شود؛ این کنترل امنیت نهایی نیست.
4. کنترل بدون مقصد وانمود به اجرای عملیات واقعی نمی‌کند.
5. README و گزارش ممیزی، تفاوت دمو و سامانه عملیاتی را روشن می‌کنند.

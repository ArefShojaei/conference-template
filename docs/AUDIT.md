# گزارش ممیزی SEO، امنیت و کیفیت

آخرین بازبینی: ۱۴۰۵/۰۸/۱۵

## محدوده

- صفحات HTML ریشه مخزن (پیش‌نمایش UI)
- پوسته WordPress در \`wordpress/themes/conference-1405\`
- افزونه گردش‌کار در \`wordpress/plugins/conference-core\`
- بررسی کد و lint؛ این گزارش جای تست نفوذ یا تست پذیرش روی WordPress واقعی را نمی‌گیرد.

## اصلاحات انجام‌شده

### SEO و crawl
- برای صفحات HTML، عنوان و توضیح متای اختصاصی اضافه/بازبینی شد.
- صفحات پنل مدیریت، پنل کاربر و صفحات احراز هویت preview با \`noindex,nofollow\` علامت‌گذاری شدند.
- لینک‌های قدیمی به \`schedule.html\` که در مخزن وجود ندارد، به صفحه تاریخ‌های مهم اصلاح شدند.
- پوسته WordPress توضیح متای fallback، Open Graph title/description/type/url و تصویر شاخص (در صفحات دارای تصویر) تولید می‌کند.
- صفحات account خصوصی در فیلتر \`wp_robots\` با noindex/nofollow پوشش داده شدند؛ پیکربندی Yoast یا Rank Math در صورت نصب اولویت دارد.

### امنیت و اعتبارسنجی
- OTP به نوع جریان ورود/ثبت‌نام bind شد؛ کد login در جریان register یا بالعکس پذیرفته نمی‌شود.
- حالت register برای شماره‌ای که از قبل حساب دارد و حالت login برای شماره بدون حساب رد می‌شود.
- محدودیت تلاش تأیید OTP بر اساس IP افزوده شد، علاوه بر محدودیت‌های درخواست کد و تلاش‌های شماره تلفن.
- schema جدول OTP دارای فیلد mode شد و migration با dbDelta در init افزوده شد.
- فایل DOCX بررسی می‌شود؛ تعداد ورودی‌های ZIP و اندازه بازشده محدود شد تا خطر ZIP bomb کاهش یابد.
- تعداد نویسندگان مقاله به ۲ تا ۳۰ و طول نام نویسنده به ۱۲۰ کاراکتر محدود شد.
- قابلیت \`upload_files\` از نقش conference_author حذف شد؛ ارسال مقاله از REST route اختصاصی با قابلیت \`submit_conference_papers\` انجام می‌شود.
- بررسی‌های nonce، capability، مالکیت مقاله/گواهی، sanitize و escape در مسیرهای موجود مرور شد.
- یک رشته JS در متاباکس رسانه با nowdoc بازنویسی شد تا PHP parse error رفع شود.

### کیفیت و تست
- تست GitHub Actions شامل PHP syntax check و Node syntax check برای فایل‌های بسته WordPress موفق است.
- اسکریپت regression برای HTML افزوده شد: title، description، robots صفحات پنل، ID تکراری، لینک/asset داخلی و fragment.
- بررسی خودکار لینک‌های HTML در حال استفاده است؛ لینک‌های ناموجود قبلی به schedule رفع شده‌اند و فایل‌های مستندات مقصد ایجاد می‌شوند.

## مواردی که هنوز باید پیش از انتشار واقعی انجام شوند

1. **فایل‌های گواهی در Media Library:** endpoint دانلود، مالکیت کاربر را بررسی می‌کند؛ اما فایل attachment که در Media Library قرار دارد ممکن است URL عمومی داشته باشد. لینک endpoint خصوصی، URL عمومی منبع را خودبه‌خود مسدود نمی‌کند. برای گواهی‌های حساس، ذخیره‌سازی خصوصی واقعی و منع دسترسی مستقیم وب لازم است؛ فایل‌های حساس را به Media Library عمومی منتقل نکنید.
2. **Nginx:** قانون deny برای \`wp-content/uploads/conference-private/\` در README نصب موجود است و باید در هاست اعمال و با URL مستقیم تست شود. فایل \`.htaccess\` افزونه فقط برای Apache/LiteSpeed است.
3. **محیط واقعی:** تست OTP با Kavenegar، ثبت‌نام، ورود/خروج، role/capability، ارسال فایل سالم و نامعتبر، دسترسی owner و رد دسترسی دیگران، صدور/دانلود گواهی، ثبت پیام و تنظیمات کش هنوز نیازمند سایت staging است.
4. **سخت‌سازی سرور:** HTTPS اجباری، به‌روزرسانی WordPress/PHP، بکاپ، WAF/rate limiting لایه سرور و security headers (از جمله HSTS و CSP با تست سازگاری) باید در هاست پیکربندی شوند.
5. **SEO عملیاتی:** در WordPress یک SEO plugin یا sitemap فعال شود؛ Search Console/Bing Webmaster Tools، canonical، schema رویداد با تاریخ/مکان واقعی، تصاویر بهینه، alt text و محتوای غیرنمونه پس از تکمیل اطلاعات بررسی شوند.
6. **محتوای preview:** اعداد، تاریخ‌ها، کاربران و نمونه‌های HTML نمایشی هستند. قبل از index شدن سایت واقعی، متن و داده‌های نمونه جایگزین شوند.
7. **تست UI:** مرورگر دسکتاپ و موبایل، keyboard navigation، screen reader و صفحات با محتواهای بلند به‌صورت دستی آزمایش شوند.

## وضعیت

اصلاحات کدی و lint به‌صورت پیوسته انجام شده‌اند؛ سامانه هنوز تا تکمیل موارد بالا و آزمون پذیرش staging نباید production-ready اعلام شود.

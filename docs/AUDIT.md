# گزارش ممیزی فنی قالب Conference Template

تاریخ: ۱۴۰۵-۰۷-۲۵  
شاخه: `chore/audit-and-static-fixes`

## خلاصه اجرایی
مخزن شامل ۲۶ صفحه HTML، یک فایل CSS اصلی و یک فایل JavaScript اصلی است. رابط فارسی و RTL نقطه شروع مناسبی دارد؛ اما فرم‌ها، ورود و پنل‌ها نمایشی‌اند و نباید به‌عنوان سامانه عملیاتی استفاده شوند. این بررسی مرور ساختار و الگوهای رایج کد است، نه ممیزی امنیتی مستقل یا آزمون کامل مرورگری.

## صفحات موجود

- عمومی: `index.html`, `about.html`, `speakers.html`, `schedule.html`, `papers.html`, `register.html`, `login.html`, `submit-paper.html`, `contact.html`, `faq.html`
- پنل کاربر: `dashboard.html`, `profile.html`, `my-papers.html`, `my-registration.html`, `certificates.html`, `messages.html`
- پنل داور: `reviewer-dashboard.html`, `review-queue.html`, `review-paper.html`, `my-reviews.html`
- مدیریت: `admin-dashboard.html`, `admin-users.html`, `admin-papers.html`, `admin-registrations.html`, `admin-reviews.html`, `admin-settings.html`

## محدودیت‌های مهم
- اعتبارسنجی مرورگر جایگزین اعتبارسنجی سمت سرور نیست.
- ورود دمو امن نیست و نباید برای حساب واقعی یا داده محرمانه استفاده شود.
- فایل مقاله در این مخزن به سرور بارگذاری نمی‌شود.
- پرداخت، داوری، پیام، صدور گواهی و ذخیره ثبت‌نام بدون backend واقعی نیستند.
- آدرس، تلفن، ایمیل، تاریخ‌ها و آمار نمونه باید پیش از انتشار تأیید شوند.
- آزمون دستی تمام صفحات در مرورگر و اجرای ابزار خودکار اعتبارسنجی HTML/CSS در این مرحله انجام نشده است.


## به‌روزرسانی رابط کاربری MVP

در شاخه `feature/mvp-visual-redesign` یک دور بازطراحی بصری انجام شده است:
- صفحه اصلی دارای اسلایدر سه‌اسلایدی با کنترل قبلی/بعدی، نقاط انتخاب، توقف حرکت خودکار و کارت کناری اطلاعات همایش است.
- ورود و ثبت‌نام دارای چیدمان مستقل، راهنمای فارسی و اعلام روشن وضعیت نمایشی هستند.
- داشبورد مدیریت دارای سلسله‌مراتب تازه برای KPIها، مقالات اخیر، ترکیب ثبت‌نام‌ها، کارهای نیازمند پیگیری و مهلت‌ها است.
- استایل مشترک RTL و واکنش‌گرا در `css/mvp-redesign.css` قرار گرفته و رفتار اسلایدر/نمایش رمز در `js/main.js` اضافه شده است.

این بازطراحی همچنان prototype است: آمار داشبورد و عکس‌های اسلایدر نمایشی‌اند، تصاویر از URL خارجی بارگذاری می‌شوند و اتصال فرم‌ها، احراز هویت، پرداخت و ذخیره داده باید در فاز backend انجام شود. آزمون نهایی در مرورگر واقعی پیش از انتشار ضروری است.

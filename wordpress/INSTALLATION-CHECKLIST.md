# راه‌اندازی روی هاست و دامنه

این راهنما برای نصب تازه‌ی سایت است. قبل از جایگزین کردن سایت فعال، از فایل‌ها و دیتابیس بکاپ کامل بگیر.

## ۱) پیش‌نیازها
- WordPress نسخه 6.2 یا بالاتر
- PHP 8.1 یا بالاتر (ترجیحاً 8.2) و افزونه‌های PHP موردنیاز وردپرس
- MySQL 8.0 یا MariaDB 10.5 یا بالاتر
- HTTPS فعال روی دامنه
- افزونه PHP یعنی `ZipArchive` برای اعتبارسنجی فایل DOCX
- `upload_max_filesize` و `post_max_size` حداقل 24M
- امکان ساخت پوشه خصوصی خارج از Document Root هاست؛ در صورت نیاز مسیر را با ثابت `CONFERENCE_PRIVATE_STORAGE_DIR` تعیین کن.

## ۲) نصب قالب و افزونه
1. فایل ZIP قالب و افزونه را از artifact خروجی GitHub Actions دریافت کن.
2. قالب `conference-1405-theme.zip` را از نمایش ← پوسته‌ها ← افزودن پوسته ← بارگذاری پوسته نصب کن.
3. افزونه `conference-core-plugin.zip` را از افزونه‌ها ← افزودن افزونه ← بارگذاری افزونه نصب کن.
4. افزونه Conference Core را فعال و سپس قالب Conference 1405 را فعال کن.
5. افزونه، برگه‌های عمومی و پنل کاربر/داور/مدیر را با مسیرهای استاندارد می‌سازد؛ قالب، فهرست اصلی و ابزارک‌های پیش‌فرض را ایجاد می‌کند.
6. از تنظیمات ← پیوندهای یکتا، یک بار ذخیره کن.

## ۳) ورود محتوای نمونه
1. از دیتابیس مقصد بکاپ بگیر.
2. در `wp-config.php` مقدار `$table_prefix` را پیدا کن.
3. در `conference-demo.sql` تمام پیشوندهای جدول `wp_` را با پیشوند واقعی جایگزین کن.
4. فایل را در دیتابیس همان نصب وردپرس از طریق phpMyAdmin وارد کن.
5. راهنمای کامل در `demo-content/SQL-IMPORT.md` است. این فایل شامل محتوای نمونه، برگه‌ها، فهرست، ابزارک‌ها و تنظیمات سفارشی‌سازی است؛ بکاپ کامل وردپرس نیست.

## ۴) پیکربندی ورود پیامکی
- کلید Kavenegar را فقط در `wp-config.php` و سمت سرور تعریف کن:
  `define('CONFERENCE_KAVENEGAR_API_KEY', 'کلید-خصوصی');`
- نام قالب‌های VerifyLookup تأییدشده برای OTP، رسید مقاله، نتیجه داوری و ثبت‌نام را در سامانه همایش ← تنظیمات پیامک وارد کن.
- کلید را در Git، فایل‌های عمومی، HTML یا JavaScript قرار نده.
- قبل از استفاده عمومی، ارسال و دریافت پیامک را با شماره واقعی و قالب تأییدشده آزمایش کن.

## ۵) ذخیره‌سازی امن مقاله‌ها
- افزونه در حالت پیش‌فرض تلاش می‌کند فایل‌ها را در `conference-private` در پوشه والد نصب وردپرس، یعنی خارج از مسیر عمومی سایت، ذخیره کند.
- اگر مسیر سفارشی لازم است، قبل از فعال‌سازی/ارسال مقاله در `wp-config.php` تعریف کن:
  `define('CONFERENCE_PRIVATE_STORAGE_DIR', '/absolute/private/path/conference-papers');`
- پوشه باید برای کاربر PHP قابل نوشتن و خارج از Document Root باشد؛ متغیر سرور `DOCUMENT_ROOT` نیز باید در درخواست‌های PHP قابل تشخیص باشد، چون افزونه در نبود آن ذخیره‌سازی را به‌صورت امن متوقف می‌کند. مسیر عمومی `uploads` فقط مسیر سازگاری قدیمی است؛ اگر هاست اجازه مسیر خارج از وب‌روت نمی‌دهد، دسترسی مستقیم Nginx/Apache را صریحاً مسدود کن.
- فایل‌ها فقط از endpoint کنترل‌شده و پس از بررسی مالکیت یا تخصیص داور دانلود می‌شوند.
- برای DOCX، `ZipArchive` باید فعال باشد؛ ساختار ZIP و سقف حجم بازشده نیز بررسی می‌شود.

## ۶) راه‌اندازی و تست پذیرش
- [ ] صفحه اصلی، اسلایدر، آمار، رنگ و اطلاعات تماس را از نمایش ← سفارشی‌سازی بررسی کن.
- [ ] فهرست اصلی و ابزارک‌های فوتر/صفحه اصلی را از نمایش ← فهرست‌ها و ابزارک‌ها مدیریت کن.
- [ ] تمام صفحات عمومی و مسیرهای ورود، ثبت‌نام، داشبورد، داور و مدیر را روی موبایل و دسکتاپ بازبینی کن.
- [ ] داده‌های نمونه و نام‌های نمایشی را قبل از انتشار اصلاح کن.
- [ ] یک حساب نویسنده واقعی با شماره موبایل تأییدشده بساز؛ نقش را مدیر اختصاص دهد.
- [ ] ورود/ثبت‌نام OTP، ارسال مقاله، دانلود مجاز و رد دانلود غیرمجاز را آزمایش کن.
- [ ] داور بساز، مقاله را تخصیص بده و نتیجه داوری و اعلان پیامکی را تست کن.
- [ ] ثبت‌نام شرکت‌کننده، پیام تماس، گواهی و اعلان‌ها را آزمایش کن.
- [ ] بکاپ خودکار دیتابیس و فایل‌ها، کش سازگار با صفحات خصوصی و مانیتورینگ خطا را فعال کن.

## مرز آماده‌بودن
مخزن، قالب و افزونه و داده نمونه و بسته‌های نصب را فراهم می‌کند؛ اما DNS/SSL، کلید پیامک، تنظیمات PHP، مجوزهای فایل، مسیر ذخیره‌سازی خصوصی و تست‌های end-to-end باید روی هاست مقصد انجام شوند. تا تکمیل چک‌لیست روی هاست واقعی، سایت را آماده بهره‌برداری عمومی تلقی نکن.

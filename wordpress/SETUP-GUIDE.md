# راهنمای کامل نصب و راه‌اندازی Conference 1405 (WordPress)

این سند مسیر نصب، پیکربندی، بررسی عملکرد و آماده‌سازی سایت را قدم‌به‌قدم توضیح می‌دهد. مسیرها نسبت به ریشه مخزن هستند. **ابتدا روی staging/local نصب کن؛ مستقیم روی سایت زنده آزمایش نکن.**

## 1. معماری پروژه و فایل‌ها

- `wordpress/themes/conference-1405/`: پوسته RTL، ظاهر صفحات، responsive، منو، اسلایدر و سفارشی‌سازی ظاهر.
- `wordpress/plugins/conference-core/`: منطق OTP موبایل، نقش نویسنده، ارسال و مدیریت مقاله، ثبت‌نام رایگان، پیام‌های تماس، گواهی‌ها و shortcodeها.
- `wordpress/demo-content/`: داده نمونه SQL و XML.
- `wordpress/INSTALLATION-CHECKLIST.md`: چک‌لیست نصب روی هاست.
- `wordpress/RECOMMENDED-PLUGINS.md`: افزونه‌های پیشنهادی.

قالب و افزونه باید جدا نصب شوند. غیرفعال/تعویض کردن پوسته نباید داده‌های برنامه را حذف کند. **Conference Core ضروری است** تا shortcodeها و گردش کار اجرا شوند.

## 2. پیش‌نیازهای سرور

- WordPress 6.2+؛ PHP 8.1+ (ترجیحاً 8.2)؛ MySQL 8 یا MariaDB 10.5+
- HTTPS/SSL فعال و گواهی معتبر
- PHP extensionهای متداول WordPress؛ `ZipArchive` برای بررسی DOCX
- `upload_max_filesize=24M` و `post_max_size=24M` یا بیشتر
- بکاپ زمان‌بندی‌شده از دیتابیس و فایل‌ها
- فضای خصوصی خارج از مسیر public web برای ذخیره مقاله‌ها
- دسترسی مدیر WordPress و دسترسی به تنظیمات PHP و وب‌سرور

در cPanel معمولاً نسخه PHP و مقادیر PHP را از **MultiPHP Manager / MultiPHP INI Editor** تنظیم می‌کنی؛ نام گزینه‌ها ممکن است با هاست فرق کند. پس از تنظیم، مقادیر را با ابزار معتبر سمت سرور بررسی کن.

## 3. دریافت بسته‌های نصب

1. مخزن را باز کن: https://github.com/ArefShojaei/conference-template
2. به تب **Actions** برو و آخرین اجرای workflow مربوط به **WordPress install packages** را انتخاب کن.
3. فقط وقتی run با وضعیت **Success** تمام شد، در بخش **Artifacts** بسته‌های ZIP را دریافت کن. Artifactهای Actions موقت‌اند و ممکن است بعد از دوره نگهداری حذف شوند.
4. اگر Artifact در دسترس نبود، از پوشه‌های زیر بسته بساز؛ محتویات پوشه باید مستقیماً ریشه پوسته/افزونه باشند، نه اینکه ZIP یک پوشه اضافیِ مخزن را در خود داشته باشد:
   - پوسته: `wordpress/themes/conference-1405/`
   - افزونه: `wordpress/plugins/conference-core/`

## 4. نصب در WordPress

### روش از پیشخوان
1. وارد `https://YOUR-DOMAIN/wp-admin` شو.
2. **نمایش ← پوسته‌ها ← افزودن پوسته ← بارگذاری پوسته**؛ ZIP پوسته را انتخاب، نصب و فعال کن.
3. **افزونه‌ها ← افزودن افزونه ← بارگذاری افزونه**؛ ZIP افزونه Conference Core را انتخاب، نصب و فعال کن.
4. پس از فعال‌سازی افزونه، صفحات پایه به صورت خودکار ایجاد می‌شوند. اگر قبلاً نصب شده، افزونه با تغییر نسخه دیتابیس، migration را اجرا می‌کند و صفحات جاافتاده را می‌سازد.
5. برو به **تنظیمات ← پیوندهای یکتا** و ساختار «نام نوشته» را انتخاب؛ دکمه ذخیره را بزن (حتی اگر از قبل همین بوده باشد).
6. برو به **تنظیمات ← خواندن** و در صورت لزوم صفحه نخست را روی نمایش صفحه اصلی سایت تنظیم کن. قالب از `front-page.php` برای صفحه نخست استفاده می‌کند.

### صفحات ایجادشده توسط افزونه
صفحه‌های پایه/عمومی از جمله این slugها ساخته می‌شوند:
`login`, `register`, `dashboard`, `submit-paper`, `papers`, `about`, `dates`, `contact`, `faq`, `speakers`, `team`, `news`, `event-registration`, `my-papers`, `certificates`, `profile`, `author-guidelines`, `certificate-info`.

صفحه‌ها را در **برگه‌ها ← همه برگه‌ها** ببین. افزونه فقط برگه‌ای را ایجاد می‌کند که slug آن وجود ندارد؛ برای صفحه‌ای که قبلاً ساخته شده، متن/محتوای آن را خودت بازبینی کن. صفحه‌ها و محتوا قابل ویرایش‌اند.

## 5. تنظیم ظاهر، منو و محتوا

1. برو به **نمایش ← سفارشی‌سازی**.
2. بخش «اطلاعات همایش»: عنوان، تاریخ، مکان، مهلت مقاله و توضیح را تنظیم کن.
3. بخش «اسلایدر صفحه اصلی»: برای هر یک از سه اسلاید تصویر، عنوان، متن کوتاه و URL دکمه را تنظیم کن. از تصویر بهینه‌شده (WebP/JPEG) با ابعاد مناسب hero استفاده کن.
4. بخش «کارت‌های ویژگی»، «تاریخ‌های مهم»، «رنگ‌بندی قالب»، «آمار صفحه اصلی» و «اطلاعات تماس و شبکه‌های اجتماعی» را تکمیل کن.
5. **نمایش ← فهرست‌ها**: منوی اصلی بساز و آن را به جایگاه «فهرست اصلی» اختصاص بده. صفحات عمومی را اضافه کن؛ لینک ورود/ثبت‌نام و داشبورد از header به صورت پویا ارائه می‌شود.
6. متن صفحات «درباره»، «FAQ»، «راهنمای نویسندگان» و «اطلاعات گواهی» را با محتوای رسمی جایگزین کن.
7. محتواهای نمونه، آدرس ایمیل/تلفن placeholder و تاریخ‌ها را قبل از انتشار اصلاح کن.

## 6. تنظیم ورود پیامکی Kavenegar (OTP)

کلید محرمانه را در فایل `wp-config.php` در سمت سرور اضافه کن، **نه در Git، قالب، HTML یا JavaScript**:

```php
define('CONFERENCE_KAVENEGAR_API_KEY', 'YOUR_PRIVATE_API_KEY');
define('CONFERENCE_KAVENEGAR_OTP_TEMPLATE', 'YOUR_APPROVED_VERIFYLOOKUP_TEMPLATE');
```

- در پنل Kavenegar قالب VerifyLookup مربوط به OTP باید تأیید شده و token کد در آن مطابق تنظیم سرویس باشد.
- کلید و نام قالب باید با مقادیر مورد انتظار حساب Kavenegar مطابقت داشته باشند.
- کلید واقعی را در چت، issue عمومی یا فایل repository نگذار.
- پس از تنظیم، یک شماره تست مجاز را برای ثبت‌نام و ورود امتحان کن؛ ارسال واقعی SMS بدون کلید و template معتبر قابل تأیید نیست.
- اگر پیام ارسال نشد، ابتدا HTTPS، کلید، template، اعتبار حساب/اعتبار پیامک و logهای سرور را بررسی کن.

## 7. نقش‌ها و گردش‌کار

- ثبت‌نام کاربران از مسیر عمومی، نقش نویسنده همایش را ایجاد می‌کند؛ کاربر نقش خود را انتخاب نمی‌کند.
- مدیر از **پیشخوان WordPress** کاربران و مقاله‌ها را مدیریت می‌کند.
- برای بررسی مقاله: از منوی «مقالات ارسالی» وارد مقاله شو؛ وضعیت/یادداشت تصمیم را بازبینی و ذخیره کن. در UI و shortcodeهای کاربری، وضعیت مقاله منعکس می‌شود.
- ثبت‌نام شرکت‌کننده رایگان است؛ پرداخت و نقش reviewer در پیاده‌سازی فعلی وجود ندارد.
- گواهی‌ها توسط مدیر صادر و از صفحه گواهی‌های کاربر ارائه می‌شوند.
- پیام‌های فرم تماس از بخش پیام‌های تماس در پنل مدیر قابل پیگیری هستند.

## 8. حفاظت فایل‌های مقاله (ضروری قبل از Production)

فایل مقاله PDF/DOC/DOCX حداکثر 20MB است و باید به شکل خصوصی ارائه شود. روی Nginx، در server block سایت، دسترسی مستقیم به مسیر ذخیره خصوصی را مسدود کن (مسیر دقیق باید با تنظیم افزونه و هاست تطبیق داده شود):

```nginx
location ^~ /wp-content/uploads/conference-private/ {
    deny all;
    return 403;
}
```

روی Apache، قانون deny فایل `.htaccess` افزونه را بررسی کن. سپس تست کن:
- کاربر A فقط مقاله متعلق به خودش را دانلود کند.
- کاربر B نتواند با URL مستقیم یا شناسه فایل، مقاله A را دریافت کند.
- مدیر مجاز به دریافت مقاله باشد.
- فایل غیرمجاز/با پسوند جعلی یا بزرگ‌تر از محدودیت رد شود.

**توجه:** قبل از اعمال تنظیمات Nginx، از پیکربندی فعلی بکاپ بگیر و syntax config را validate کن؛ تغییر نادرست می‌تواند سایت را از دسترس خارج کند.

## 9. ورود محتوای نمونه (اختیاری)

- SQL: `wordpress/demo-content/conference-demo.sql`
- دستورالعمل SQL: `wordpress/demo-content/SQL-IMPORT.md`
- XML: `wordpress/demo-content/conference-demo.xml`

برای SQL، ابتدا افزونه را فعال کن، بکاپ دیتابیس بگیر، پیشوند `wp_` را با پیشوند واقعی سایت جایگزین و فایل را به دیتابیس **همان سایت** import کن. SQL نمونه ممکن است اطلاعات/رکوردهای نمونه وارد کند؛ روی سایت زنده بدون بررسی اجرا نکن. برای XML از ابزار واردکننده WordPress استفاده کن و موارد تکراری را بررسی کن.

## 10. تست پذیرش قبل از انتشار

- [ ] SSL و پیوندهای یکتا کار می‌کنند؛ صفحه اصلی و صفحات داخلی بدون 404 باز می‌شوند.
- [ ] صفحات login/register/dashboard/submit-paper/my-papers/profile/certificates در برگه‌ها موجودند.
- [ ] header، منوی موبایل، اسلایدر، تصاویر، فونت/RTL و responsive روی موبایل/تبلت/دسکتاپ بررسی شده‌اند.
- [ ] OTP ثبت‌نام و ورود با شماره واقعی تست شده است.
- [ ] نقش نویسنده جدید درست تعیین شده و امکان انتخاب نقش توسط کاربر وجود ندارد.
- [ ] ارسال PDF، DOC، DOCX؛ حد 20MB؛ خطا برای فایل نامعتبر تست شده.
- [ ] مقاله کاربر دیگر از راه مستقیم قابل دانلود نیست؛ مدیر می‌تواند بررسی کند.
- [ ] مدیر وضعیت مقاله و یادداشت تصمیم را ذخیره می‌کند و وضعیت در پنل کاربر دیده می‌شود.
- [ ] ثبت‌نام رایگان شرکت‌کننده و فرم تماس، پیام مدیر و صدور/دانلود گواهی تست شده‌اند.
- [ ] اطلاعات نمونه و placeholderها حذف/اصلاح شده‌اند.
- [ ] بکاپ و بازیابی آزمایشی دیتابیس و فایل‌ها انجام شده است.
- [ ] log خطاهای PHP/WordPress و سلامت امنیتی بررسی شده‌اند.

## 11. عیب‌یابی

### برگه‌ها ایجاد نشده‌اند
- افزونه Conference Core را فعال کن و صفحه برگه‌ها را refresh کن.
- نسخه افزونه باید جدیدترین نسخه repository باشد؛ ارتقای نسخه دیتابیس migration را فعال می‌کند.
- اگر صفحه‌ای با همان slug وجود دارد، افزونه آن را دوباره ایجاد نمی‌کند؛ صفحه trash یا draft را هم بررسی کن.
- اگر صفحات پس از نصب هنوز 404 هستند: **تنظیمات ← پیوندهای یکتا ← ذخیره تغییرات**.

### shortcode به صورت متن دیده می‌شود یا صفحه خالی است
- Conference Core فعال باشد.
- متن shortcode را عیناً در محتوای صفحه بررسی کن.
- log PHP را بررسی کن؛ افزونه یا قالب دیگری ممکن است با آن تداخل داشته باشد.

### استایل یا JS قدیمی نمایش داده می‌شود
- cache افزونه، CDN، cache هاست و مرورگر را پاک کن.
- مطمئن شو نسخه جدید پوسته فعال است و فایل‌های `assets/css` و `assets/js` در بسته نصب وجود دارند.

### ارسال مقاله/دانلود مشکل دارد
- مقادیر PHP upload/post حداقل 24M و فضای دیسک کافی باشد.
- `ZipArchive` برای DOCX فعال باشد.
- قوانین Nginx/Apache و مسیر ذخیره خصوصی و permissionها بررسی شوند.

### OTP ارسال نمی‌شود
- API key و VerifyLookup template در `wp-config.php`، تأیید قالب و وضعیت حساب Kavenegar را بررسی کن.
- logهای PHP/server را بررسی کن؛ هیچ کلید محرمانه‌ای را در log عمومی یا ticket قرار نده.

## 12. حد آمادگی Production

CI موفق فقط lint/package check است و **به معنی تست روی هاست واقعی نیست**. پیش از انتشار، تست‌های بخش 8 و 10 باید در محیط واقعی با دامنه/SSL، دیتابیس، SMS account، تنظیمات وب‌سرور و حساب‌های مجاز انجام شوند. DNS، SSL، بکاپ، محدودیت‌های PHP، تنظیم Nginx/Apache و ارسال پیامک را مالک هاست باید پیکربندی کند.
